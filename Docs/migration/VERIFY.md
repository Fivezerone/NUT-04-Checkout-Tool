| **A-04** | Does `background.js` call catalogue sync on every worker wake? | **Confirmed** | `src/extension/background.js:215-216`<br>`src/extension/background.js:114-129`<br>`src/extension/catalog-sync.js:427-433` | `ensureCatalogReady()` is invoked at top level on line 216 on every service worker cold wake, invoking `NutriCatalogSync.ensureReady()` which calls `await sync()`. | **E-05** | Where, if anywhere, are warnings gated on `ReviewState`? | **Confirmed** (Absent / Unenforced) | `src/extension/background.js:363-430`<br>`src/extension/pipeline/disease-engine.js:66-180`<br>`src/ui/src/app/lib/db/grading.ts:250` | `DiseaseEngine.evaluate` does not check `ReviewState` at all. | **F-01 & F-02** | How does Keycloak enforce MFA for `cad-web-ui`, and do server functions verify JWTs? | **Confirmed** (Client-side stub & no MFA enforcement) | `infra/keycloak-realm.json:208-220`<br>`src/ui/src/cad/context/AuthContext.tsx:247-255`<br>`src/ui/src/cad/components/MfaChallenge.tsx:25` | `cad-web-ui` in Keycloak has `directAccessGrantsEnabled: true`, but zero OTP/MFA executions or required actions are configured. `AuthContext.tsx:247-255` implements a stub `verifyMfa(code)` that accepts any 6-digit regex and unconditionally writes `cad_mfa_verified = true` to `sessionStorage`. **WP-09** removes this client stub and enforces server-supplied assurance; **WP-14** introduces the BFF confidential client. |
| **F-03** | How does the browser REST client authenticate (cookie or header)? | **Confirmed** | `src/ui/src/services/storage.ts:37-41`<br>`src/ui/src/services/storage.ts:77-124` | `PostgrestQueryBuilder` initializes headers with only `Accept` and `Content-Type`. | **A-06** | Does observed-orders de-duplicate on `Idempotency-Key` header? | **Confirmed** (Regenerated key & cleartext default) | `src/extension/observed-orders-sync.js:23`<br>`src/extension/observed-orders-sync.js:37-39`<br>`src/extension/observed-orders-sync.js:51-55` | Line 23 defaults `backendUrl` to cleartext `http://127.0.0.1:54321`. No `Idempotency-Key` HTTP header is sent (it is only sent as a JSON body property). **WP-01** hotfix changes key derivation to `obs-${retailer}-${sha256(canonicalJson(payload))}` and eliminates the cleartext default; **WP-12** implements the full telemetry client. |
| **X-03(d)** | Where is `Subject.acr` built from `CanonicalClaims.acr`, and is it numeric? | **Confirmed** (Type mismatch & no production builder) | `src/shared/claims.ts:24`<br>`src/shared/claims.ts:82`<br>`src/shared/authz.ts:19` | In `claims.ts`, `CanonicalClaims.acr` is typed `string | undefined` (derived from JWT `acr` or `aal`). There is no production function mapping `CanonicalClaims` to `Subject` (instantiated only manually in test fixtures). **WP-05** defines explicit `AcrLevel = 0 \| 1 \| 2 \| 3` and canonical claim mapping. |
